# 老化板端实施规格（spaceTest3576 · aging_test 分支）

上位机侧（SpaceTestPC.AgingStation + SpaceTestPC.Core）已按本契约实现完毕并编译通过。
板端按本文实现即可联调。字段名与上位机 C# 模型**逐字对应**（camelCase），改一个字母就会对不上。

---

## 1. 传输

沿用既有 PCBA 的控制面协议：

| 项 | 值 |
|---|---|
| 传输 | TCP，**19001** |
| 帧格式 | 行分隔 JSON：请求一行，以 `\n` 结尾；响应一行 |
| 连接 | 上位机**每命令一条短连接**，发完即关。板端不需要保持会话 |
| 编码 | UTF-8 |
| 序列化 | camelCase，未知字段忽略 |

### 请求信封

```json
{"protocolVersion":"1.0","requestId":"<uuid>","sessionId":"","sn":"","boardId":"","commandGroup":"aging","command":"start","parameters":{...},"timestamp":"2026-09-20T12:00:00+08:00"}
```

### 响应信封

```json
{"protocolVersion":"1.0","requestId":"<回显>","sessionId":"","sn":"SN123","boardId":"","resultCode":0,"message":"","timestamp":"...","data":{...}}
```

- `resultCode = 0` 成功，非 0 失败
- `data` 为各命令的返回体，失败时可缺省
- **必须回显 `requestId`**

## 2. 命令契约

### 2.1 `aging.start`

启动一次老化。**立即返回**，后台起任务——上位机不会等你跑完。

parameters：

```json
{
  "runId": "run-20260920-120000-s03",
  "sn": "SN123456",
  "durationSec": 86400,
  "startDelaySec": 47,
  "debugMode": false,
  "enableLvgl": true,
  "reportIntervalMs": 60000,
  "maxResumeCount": 2,
  "items": {
    "camera_record_emmc": {"enabled":true,"resolution":"1080p30","segmentMinutes":10,"lowWaterMarkGiB":5,"maxTotalWriteGiB":80},
    "cpu_load": {"enabled":true,"targetPercent":30},
    "mem_load": {"enabled":true,"targetPercent":30},
    "ethernet_transfer": {"enabled":true,"intervalMinutes":30,"payloadMiB":256,"minMbps":20},
    "audio_playback": {"enabled":true,"intervalMinutes":60},
    "fan": {"enabled":true,"minRpm":1},
    "battery_soc": {"enabled":true,"chargeMode":true},
    "lvgl_display": {"enabled":true}
  }
}
```

`data`：

```json
{"runId":"run-20260920-120000-s03","state":"PREPARING"}
```

**关键语义**：

| 字段 | 含义 |
|---|---|
| `startDelaySec` | 预约倒计时（秒）。> 0 时先进 `PREPARING`，**本地倒计时归零后才开始计有效时长** |
| `0` | 立即开始 |
| `runId` 幂等 | 已有相同 `runId` 的 job 时返回当前状态，**不重启、不重复计时** |
| busy | 上轮未清理（`media/` 非空）或升级中 → 返回非 0，上位机标记该槽位失败且不阻塞其它槽位 |

倒计时用**相对秒数**在设备本地跑：不依赖上位机在线，也不依赖设备间时钟同步。

### 2.2 `aging.stop`

停止负载。`data` 可缺省。返回非 0 表示拒绝（如未在跑）。

### 2.3 `aging.status`

上位机每 30 s 对每台轮询一次（32 路并行）。这是上位机唯一的进度来源，必须快（< 1 s）。

`data`：

```json
{
  "runId": "run-20260920-120000-s03",
  "sn": "SN123456",
  "state": "RUNNING",
  "failReason": null,
  "lastError": null,
  "effectiveSec": 3600,
  "remainingSec": 82800,
  "prepareRemainingSec": 0,
  "resumeCount": 0,
  "lostTimeSec": 0,
  "startedAtUtc": "2026-09-20T04:00:47Z",
  "updatedAtUtc": "2026-09-20T05:00:12Z",
  "mediaPresent": true,
  "mediaBytes": 32212254720,
  "items": { }
}
```

| 字段 | 说明 |
|---|---|
| `state` | `IDLE` / `PREPARING` / `RUNNING` / `CLEANING` / `WAITING_MANUAL_CHECK` / `PASSED` / `FAILED` |
| `effectiveSec` | **累计有效运行时长**，不是墙钟时间 |
| `mediaPresent` / `mediaBytes` | 上位机判断"现场还在不在"的唯一依据（§12.1 取证） |
| `items` | 各测试项实时摘要，结构自定，上位机透传 |

### 2.4 `aging.result`

设备自评结论，**唯一真相源**。未结束时返回非 0（上位机视为"尚无结论"，不报错）。

`data`：

```json
{
  "runId": "run-20260920-120000-s03",
  "sn": "SN123456",
  "verdict": "PASS",
  "failReason": null,
  "failedAtUtc": null,
  "startedAtUtc": "2026-09-20T04:00:47Z",
  "finishedAtUtc": "2026-09-20T04:00:47Z",
  "effectiveSec": 86400,
  "resumeCount": 1,
  "lostTimeSec": 120,
  "debugMode": false,
  "cleanup": {
    "ok": true,
    "beforeFreeGiB": 3.2,
    "afterFreeGiB": 33.5,
    "durationSec": 42,
    "mediaPresent": false
  },
  "items": { }
}
```

### 2.5 `aging.cleanup`

删除 `media/`，恢复出货状态（§8.9）。**删几十 GB 可能要几分钟**，上位机超时为 `cleanup.timeoutSec × 1000`（默认 300 s，最小 60 s）。

parameters：

```json
{"scope":"media"}
```

| scope | 行为 |
|---|---|
| `media` | 只删 `/userdata/factory_test/aging/media/`（常规清理） |
| `all` | `media/` + 元数据一并删除（出货前 / 返修前彻底复位） |

`data`：

```json
{"ok":true,"beforeFreeGiB":3.2,"afterFreeGiB":33.5,"durationSec":42,"mediaPresent":false}
```

**`ok=false` 是关键失败**，上位机会标红并禁止出货。

## 3. 目录与文件契约（§5.2）

```text
/userdata/factory_test/aging/          元数据区（KB 级，保留至回收）
  job.json      下发即落盘（入参、SN、时长、各项参数）
  state.json    周期 fsync（当前项、elapsedSec、累计指标、resumeCount）
  events.jsonl  明细
  result.json   结束结论（设备自评，唯一真相源）
  media/                               大数据区（GB 级，测完整体删除）
    rec/        录像分段（camera_record_emmc）
    tmp/        其它临时产物
```

| 规则 | 说明 |
|---|---|
| 大数据只准落在 `media/` | 录像、临时文件一律写 `media/` 下，**禁止**写到 `aging/` 根或任意其它路径 |
| 路径固定 | `media/` 由板端常量定义，`aging.start` **不带**路径参数 |
| 清理 = 删 `media/` 一个目录 | 不做逐文件匹配，避免漏删与误删 |
| 元数据保留至回收 | 上位机收走后才可清，或由下一轮 `start` 覆盖 |

写文件采用"先写 `.tmp` 再 rename"并 `fsync`，保证掉电安全。

**删除红线**：目标恒为 `media/`，不接受外部传入路径，不做通配符匹配；删除前校验路径非空且位于 `aging/` 下（防空变量导致 `rm -rf /`）。

## 4. 状态机（§5.3）

```text
IDLE → PREPARING（倒计时）→ RUNNING → CLEANING → WAITING_MANUAL_CHECK → PASSED / FAILED
                                │                        ↑
                                └─ 关键失败 ─────────────┘（保留现场，跳过清理）
```

| 状态 | 要点 |
|---|---|
| `PREPARING` | 只做倒计时与启动前自检，**不计有效时长**；期间掉电重启后继续倒计时 |
| `RUNNING` | 计有效时长 |
| `CLEANING` | **仅正常达标路径**：删 `media/` + 校验 + 写 `cleanup` 字段 |
| `WAITING_MANUAL_CHECK` | 终检态，也是关键失败后的**冻结态** |
| 关键失败 | **跳过 `CLEANING`**，录像作为证据保留，等人工处置 |

---

## 5. 关键约束

1. **判定在设备端。** 上位机只是下发与收集，不判定。`result.json` 是唯一真相源。
2. **上位机全程可断。** 断线、重启、关闭上位机都不影响老化继续；恢复后用 `status` / `result` 拉回。严禁把"上位机断开"实现为"老化中止"。
3. **未收到 `aging.start` 时零副作用。** 不创建老化线程、不占资源（板端硬要求）。
4. **有效时长按累计，不按墙钟。** 掉电续跑记 `resumeCount` / `lostTimeSec`，超限 `maxResumeCount` 后记异常。
5. **清理失败是关键失败**，不能把几十 GB 残留交给客户。

## 6. 联调自测（不依赖上位机）

板端先起一个监听，用 `nc` 手工喂报文验证：

```bash
# 起监听
while true; do nc -l -p 19001 -q 1 < /dev/null; done

# 手工发一条 start（单行 JSON + 换行）
printf '%s\n' '{"protocolVersion":"1.0","requestId":"t1","commandGroup":"aging","command":"start","parameters":{"runId":"run-test-001","sn":"SN001","durationSec":600,"startDelaySec":5,"debugMode":true,"enableLvgl":false,"reportIntervalMs":60000,"maxResumeCount":2,"items":{}}}' | nc 127.0.0.1 19001
```

自检清单：

- [ ] `start` 立即返回（不阻塞），`data.state = PREPARING`
- [ ] `startDelaySec` 秒后才开始计 `effectiveSec`
- [ ] 同一 `runId` 重复下发不重启、不重复计时
- [ ] `media/` 非空时 `start` 返回 busy（非 0）
- [ ] `status` 响应 < 1 s，字段齐全
- [ ] 达标后自动清理，`status` 显示 `mediaPresent=false`
- [ ] 制造一次关键失败：验证**不清理**、`media/` 仍在、`state=WAITING_MANUAL_CHECK`
- [ ] 掉电重启后自动 resume，`resumeCount` +1

## 7. 上位机侧已实现（对照用）

| 上位机文件 | 内容 |
|---|---|
| `SpaceTestPC.Core/Models/AgingRunStates.cs` | 状态常量 |
| `SpaceTestPC.Core/Models/AgingEnvelope.cs` | 响应信封 |
| `SpaceTestPC.Core/Models/AgingStartRequest.cs` | start 请求 / 应答 |
| `SpaceTestPC.Core/Models/AgingStatusSnapshot.cs` | status / result / cleanup 模型 |
| `SpaceTestPC.Core/Services/AgingCommandClient.cs` | 命令客户端 |
| `SpaceTestPC.AgingStation/Services/AgingStationCoordinator.cs` | 启动编排、轮询、清理 |
| `SpaceTestPC.AgingStation/appsettings.json` | 32 槽位配置（IP 需按实际改） |

启动编排要点：批量启动按槽位序号**依次错开** `batchStaggerSec`（默认 30 s/台），
每台单独算 `startDelaySec = 计划开始时刻 − 下发时刻`，因此 `startDelaySec` 会各不相同，
这是预期行为，不是配置错误。
